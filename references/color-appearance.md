# 颜色选择与当前资源清单

## 两种不同的形态

模型形态由唯一实体和 `form_asset` 确定，例如“本来的样子”“看守果实的样子”。颜色类型独立确定。同一模型的异色素材仍须放在独立的 shiny 标准目录；不要通过用户一句“正常”同时猜模型和颜色。

颜色类型保留以下九类，黑白的稀有类型不并入常规炫彩；赛季是独立的动态预设列表，名称和数量由当前资源确定。

| 用户类型 | color_type | 基础目录 | 效果 |
|---|---|---|---|
| 常规 | normal | normal | 无 |
| 常规炫彩 | normal_glassy | normal | 当前配色＋粒子/纹样 |
| 黑白炫彩 | normal_black_white | normal | 当前黑白预设 |
| 赛季限定炫彩 | normal_seasonal | normal | 当前赛季预设 |
| 污染 | pollution | normal | 原污染效果 |
| 异色 | shiny | shiny | 无 |
| 异色炫彩 | shiny_glassy | shiny | 当前配色＋粒子/纹样 |
| 异色赛季炫彩 | shiny_seasonal | shiny | 当前赛季预设 |
| 异色黑白炫彩 | shiny_black_white | shiny | 当前黑白预设 |

污染按独立效果处理，不因为它起源于某个赛季就自动等同于那个赛季预设。污染与异色互斥，也不与另一种炫彩叠加。黑白与异色黑白在本地 appearance 元数据中各有明确类型；不假定 Pets 提供游戏图标或游戏收益机制。

## 如何询问

1. 使用用户明确指定或已在上下文确定的内容，不重复确认。用户明确授权自行选择时，可从当前可用项选择并记录依据。
2. 未提颜色：询问九类中的哪类。输入 palette 只能说明现有素材，不能替用户作出颜色选择；异色选择需要对应 shiny 输入，不能凭空变色。
3. 只说“炫彩”：澄清常规、黑白、赛季或污染，以及是否异色。只说“正常”：澄清它指模型形态还是常规颜色，已知部分不重问。
4. 常规炫彩已确定：只补问缺少的配色或粒子。可用 ID 或当前清单中的唯一精确名称选择，不随机挑一组。
5. 赛季类型已确定：先读取当前输入 effects.json / glassy.json，把其中 `season: true` 的条目列给用户；用户已明确唯一赛季则直接采用。名称、ID、数量和赛季编号不保存在 skill 的枚举中。找不到指定项时说明当前资源缺失，不把未来赛季映射到旧赛季。
6. 黑白类型明确且当前资源有唯一条目时，不再问普通炫彩的配色和粒子。污染也不问这两项。

优先用简短选择题，长配色列表可按当前名称分组询问。题目只来自当前数据；不要虚构“第五季”作为选项。缺失资源与缺少偏好分别说明，偏好未确定时可以继续只读校验、动作枚举，但不生成依赖该选择的成品。

## 结构化选择

渲染计划中的 `appearance` 使用下列之一；`color_type` 可写上表的英文标识或中文名称：

```json
{"color_type":"常规"}
```

```json
{"color_type":"异色炫彩","color_id":33,"particle_id":3}
```

```json
{"color_type":"黑白炫彩"}
```

```json
{"color_type":"污染"}
```

赛季选择使用当前列表的 `preset_id`、`preset_name` 或 `season_no`。多个字段同时提供时必须一致；不能在旧的名称数组中查找。常规配色可用 `color_name` 替代 color_id，纹样可用 `particle_name` 替代 particle_id，名称必须在当前清单中唯一且准确。

使用 `python scripts/color_appearance.py --input <标准目录> --selection <选择.json> --json-out <私有结果.json>` 校验结构化选择。退出码 0 表示已解析，2 表示需要用户补充选择（输出 questions），1 表示输入/资源或互斥错误。没有指定 --selection 时只列当前选项。

解析结果保存 `color_type`、中文标签、基础 palette、效果、所选预设 ID、共享资源哈希与完整 `variant_key`。输出目录按 variant_key 隔离。资源路径与完整本地元数据不写进公开仓库。

## 原生渲染与时间

普通/异色的基础材质已经在输入中选定。其上叠加炫彩时只给原渲染器 `炫彩:<粒子ID>/<配色ID>` 或 `炫彩:<预设名>`，不要对已选 shiny 材质再次切换异色。污染使用已验证的 `炫彩:污染`。

当前接口从 `--packs-dir <glassy目录的父目录>` 读取共享数据。每种预设所需的共享纹理、目录清单和 SHA-256 必须通过检查。已有新赛季条目并不保证旧版渲染器已支持其所有新 shader；渲染失败时保留实际日志，不做静默降级。

每帧 `seconds` 采样原骨骼动作，`shader_time` 单独驱动流动、闪点和图案。两者不可混为一项。`render_source.py` 按 shader 时间分批，每批仍包含整组完全相同的静态姿势，使自动构图依据一致，再提取所需格子。

完整动画要检查各状态内的材质时间推进、首末相位接缝、状态切换，以及缩到最终尺寸后的闪烁。有限帧精灵表不具备连续实时材质时钟。静态基准方向可以用同一相位，制作完整动作行时不能无意把全部相位固定成零。

保留原参数、原遮罩和原图集，不根据实验中人为清零的纹理或参数制作成品。沿用原生渲染，不要求通过重写或猜测完整 UE shader 来完成常规流程。
